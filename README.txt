POSITIONAL INDEX FOR TELUGU

ASSIGNMENT OVERVIEW
This project builds a positional index for Telugu text. For each vocabulary
term, the index records its collection frequency (CF), document frequency
(DF), and token positions in each document. The search program keeps the
vocabulary and its postings offsets in memory while reading positional
postings from disk as needed.

DATASET
The collection contains six Telugu Wikipedia articles: Hollywood, Hindi
cinema, Telugu cinema, Tamil cinema, Malayalam cinema, and Kannada cinema.
WikiDownloader.java retrieves article text from the Telugu Wikipedia API
using the titles in titles.txt. Running WikiDownloader creates the
WikiExtractor-format collection at data\wiki.txt. The collection contains six
articles, and the dataset file is included in this repository.

Data and index Git Link : https://github.com/harish-3558/IR_Course_Assignment.git

REQUIREMENTS
- Java 11 or later
- No external Java libraries
- UTF-8 terminal/output support for displaying Telugu correctly

BUILD AND RUN (WINDOWS POWERSHELL)
From the project root, run:

    chcp 65001
    cd .\src
    javac -encoding UTF-8 *.java
    java "-Dfile.encoding=UTF-8" WikiDownloader te ..\titles.txt ..\data\wiki.txt
    java "-Dfile.encoding=UTF-8" Indexer ..\data\wiki.txt ..\index
    cmd /c 'java "-Dfile.encoding=UTF-8" Search ..\index < ..\queries.txt > ..\output.txt'

The last command saves ten rare-term examples and the five test queries in
output.txt. To search interactively instead, run
java "-Dfile.encoding=UTF-8" Search ..\index and enter terms, phrases, :rare,
or :quit. The data and index folders are generated by the commands above.

MODULES
- WikiDownloader.java - Downloads the requested Wikipedia articles and
  saves them as <doc ...> ... </doc> records.
- Tokenizer.java - Splits text into tokens, retaining letters, digits,
  combining marks, and Telugu joiners. Token positions start at 1.
- Indexer.java - Reads article records, assigns document IDs, and creates
  positional postings. It writes sorted temporary blocks after every 1,000
  documents, then merges them into the final index files.
- Search.java - Loads the vocabulary into a HashMap in memory and reads
  postings from disk by byte offset. Supports term lookup, phrase search, and
  :rare.

INDEX FILES
- index\vocab.txt - Term, collection frequency (CF), document frequency
  (DF), byte offset, and postings length.
- index\postings.txt - Positional postings stored on disk in the format
  docID:pos1,pos2;docID:pos1,...
- index\docs.txt - Document IDs and article titles.

CF is the total number of occurrences of a term in the collection. DF is the
number of documents containing that term.

TEST OUTPUT
output.txt contains ten rare-term examples followed by five search test
cases: two term queries, two phrase queries, and one term-not-found query.
Each rare-term result includes CF, DF, document, and positional-index details.
